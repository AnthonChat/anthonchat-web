# Internationalization (i18n)

This project uses [`next-intl`](https://next-intl-docs.vercel.app/) for internationalization and localization.

## Configuration

The i18n configuration is split across three main files:

1.  **`src/i18n/routing.ts`**: Defines supported locales and navigation helpers.
2.  **`src/i18n/request.ts`**: Loads translation messages for the current request.
3.  **`src/middleware.ts`**: Handles locale detection and routing (redirects/rewrites).

## Supported Locales

- **English** (`en`) - Default
- **Italian** (`it`)

## Translation Files

Translations are stored in JSON files within the `src/locales` directory:

- `src/locales/en.json`
- `src/locales/it.json`

The structure of the JSON files is nested, grouping translations by feature or component (e.g., `Auth`, `Dashboard`, `Landing`).

## Adding a New Language

To add support for a new language (e.g., French):

1.  **Update Routing**: Add `'fr'` to the `locales` array in `src/i18n/routing.ts`.
    ```typescript
    export const locales = ['en', 'it', 'fr'] as const;
    ```
2.  **Create Translation File**: Create `src/locales/fr.json` and copy the structure from `en.json`.
3.  **Translate**: Translate the values in `fr.json`.

## Usage

### Client Components

Use the `useTranslations` hook:

```tsx
import { useTranslations } from 'next-intl';

export default function MyComponent() {
  const t = useTranslations('MyComponent');
  return <h1>{t('title')}</h1>;
}
```

### Server Components

Use the `getTranslations` async function:

```tsx
import { getTranslations } from 'next-intl/server';

export default async function MyServerComponent() {
  const t = await getTranslations('MyServerComponent');
  return <h1>{t('title')}</h1>;
}
```
